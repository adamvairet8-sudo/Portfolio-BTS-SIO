L'automatisation par l'IA avec n8n et Python : opportunités et risques pour l'administrateur systèmes et réseaux

Mon sujet de veille

Pourquoi j'ai choisi l'automatisation par l'IA

Problématique

Comment l'intelligence artificielle transforme-t-elle l'automatisation des tâches informatiques avec des outils comme n8n et Python, et quels nouveaux risques de sécurité cela introduit-il pour une infrastructure ?

Un administrateur systèmes et réseaux passe une grande partie de son temps sur des tâches répétitives : créer des comptes, traiter des tickets, surveiller des alertes, produire des rapports. Depuis 2025, une nouvelle génération d'outils permet de confier ces tâches à des workflows automatisés pilotés par des modèles d'IA (LLM), capables de lire un texte, de le classer et de décider de l'action à mener.

J'ai choisi ce thème parce qu'il relie directement mes deux centres d'intérêt du BTS SIO SISR : l'infrastructure (déployer, héberger et maintenir ces outils) et la cybersécurité (un outil qui détient les accès à tous les services de l'entreprise devient une cible prioritaire).

n8n

Plateforme d'automatisation « low-code » créée à Berlin en 2019. On construit des workflows en reliant des nœuds sur un canevas visuel, et elle peut être auto-hébergée (Docker), ce qui intéresse particulièrement un profil SISR.

Low-codeAuto-hébergeable+1 000 intégrations

Python

Le langage de référence de l'administration système et de l'IA. Il sert à écrire des scripts d'automatisation et des agents IA avec des frameworks comme LangChain / LangGraph ou Pydantic AI, avec un contrôle total sur le code.

ScriptingAgents IAOpen source

IA & agents

Un agent IA est un LLM à qui l'on donne des outils (envoyer un mail, créer un ticket, interroger une base) et qui décide lui-même lesquels utiliser. C'est puissant, mais chaque outil confié est aussi un risque.

Les notions clés

Le vocabulaire indispensable pour comprendre le sujet

Workflow

Suite d'étapes automatisées qui s'enchaînent : un événement déclenche une série d'actions sans intervention humaine.

Déclencheur (trigger)

Ce qui lance le workflow : une heure précise, un mail reçu, ou un webhook (une URL appelée par un autre logiciel).

LLM

Large Language Model : modèle d'IA qui comprend et génère du texte (Claude, GPT, Mistral, Llama…). Il peut tourner dans le cloud ou en local (Ollama).

Agent IA

Un LLM capable d'utiliser des outils et d'enchaîner plusieurs actions pour atteindre un objectif, en choisissant lui-même les étapes.

MCP

Model Context Protocol : protocole standard qui permet à une IA de découvrir et d'appeler des outils. n8n peut être client MCP et serveur MCP.

Injection de prompt

Attaque qui consiste à cacher des instructions dans un texte lu par l'IA (mail, page web, ticket) pour la détourner de sa mission.

Mon constat

Ce n'est pas « l'un ou l'autre ». n8n orchestre (il relie les services et rend l'automatisation lisible par toute l'équipe) et Python calcule (traitements complexes, logique métier). Depuis n8n 2.0, on peut d'ailleurs exécuter du Python natif directement dans un nœud Code.

Cas d'usage étudié

Trier automatiquement les alertes de sécurité d'une PME

Déclencheur

Un webhook n8n reçoit une alerte envoyée par le pare-feu (pfSense) ou l'antivirus.

Nettoyage

Un nœud Code en Python extrait l'IP, la machine et le type d'événement, et masque les données personnelles.

Analyse IA

Un nœud AI Agent classe la gravité (faible, moyenne, critique) et rédige un résumé en français.

Décision

Si l'alerte est critique : ticket GLPI et message Teams à l'astreinte. Sinon : simple journalisation.

Validation humaine

Un technicien valide avant toute action corrective : l'IA propose, l'humain décide.

Côté Python : envoyer l'alerte

import os
import requests

alerte = {
    "source": "pfSense",
    "ip": "192.168.10.42",
    "evenement": "5 echecs de connexion SSH",
}

reponse = requests.post(
    "https://n8n.lab.local/webhook/alertes",
    json=alerte,
    # Le secret vient d'une variable d'environnement,
    # jamais ecrit en dur dans le script
    headers={"X-Webhook-Token": os.environ["N8N_TOKEN"]},
    timeout=10,
)
reponse.raise_for_status()

Les mesures de sécurité

  • Interface n8n non exposée sur Internet : accès via VPN ou reverse proxy authentifié
  • Webhook protégé par un jeton secret transmis dans un en-tête
  • Compte de service avec le minimum de droits (principe du moindre privilège)
  • L'IA ne peut rien exécuter seule : aucune action corrective sans validation
  • LLM local (Ollama) si les alertes contiennent des données sensibles (RGPD)
  • Nœuds communautaires désactivés et mises à jour suivies via les avis de sécurité

15 décembre 2025 Documentation officielle n8n

n8n 2.0 : une version majeure tournée vers la sécurité

n8nPythonDurcissement

Publiée en version stable le 15 décembre 2025, n8n 2.0 est présentée comme une version de « durcissement ». Le code des nœuds Code s'exécute désormais dans des processus isolés (task runners), si bien qu'une boucle infinie ou un script malveillant ne peut plus faire tomber toute la plateforme. Le nœud Python passe d'une émulation dans le navigateur (Pyodide) à du Python natif, exécuté par une image Docker séparée. Enfin, l'enregistrement et la publication d'un workflow sont dissociés, pour ne plus casser la production en cours d'édition. Le support de la version 1.x s'est arrêté en mars 2026.

Mon analyse

On retrouve les principes vus en cours : isolation, cloisonnement, sécurité par défaut. Côté administration, c'est aussi un cas concret de gestion de version majeure : avec seulement trois mois avant la fin du support, il faut un environnement de test, une sauvegarde et un plan de retour arrière avant de migrer.

7 janvier 2026 The Hacker News Ravie Lakshmanan

« Ni8mare » : une faille critique permet de prendre le contrôle de n8n sans mot de passe

CVE-2026-21858CVSS 10.0RCE

Un chercheur a découvert qu'un formulaire public n8n ne vérifiait pas le type de contenu des requêtes reçues. En forgeant une requête, un attaquant non authentifié pouvait lire n'importe quel fichier du serveur, récupérer les secrets de la base de données, se fabriquer une session administrateur et enfin exécuter des commandes. La faille a été corrigée dans la version 1.121.0 (18 novembre 2025). Au moment de la publication, Censys recensait plus de 26 500 instances exposées sur Internet, dont environ 2 650 en France.

Mon analyse

C'est l'article qui m'a le plus marqué. Un outil d'automatisation détient les accès de tous les services qu'il pilote : le compromettre revient à obtenir les clés de toute l'entreprise. Les leçons sont des fondamentaux SISR : ne pas exposer une interface d'administration sur Internet, tenir un inventaire des logiciels et appliquer les correctifs rapidement.

12 janvier 2026 The Hacker News Ravie Lakshmanan

De faux nœuds n8n volent les jetons OAuth des utilisateurs

Supply chainnpmOAuth

Des chercheurs d'Endor Labs ont identifié huit paquets npm malveillants qui se présentaient comme des intégrations n8n (par exemple pour Google Ads). Ils affichaient un vrai formulaire de configuration, puis utilisaient la clé maîtresse de n8n pour déchiffrer les jetons OAuth stockés et les envoyer vers un serveur contrôlé par les attaquants. En cause : les nœuds communautaires s'exécutent avec les mêmes droits que n8n, sans bac à sable. n8n recommande de n'utiliser que les intégrations officielles et de désactiver les nœuds communautaires sur les instances auto-hébergées.

Mon analyse

Le même risque existe côté Python avec les paquets malveillants publiés sur PyPI. Installer une extension, c'est lui faire confiance avec tous ses droits. En entreprise, il faut une liste des extensions autorisées, des versions figées et une vérification de la provenance avant toute installation.

26 décembre 2025 The Hacker News Ravie Lakshmanan

« LangGrinch » : une faille critique dans LangChain, le framework Python des agents IA

CVE-2025-68664CVSS 9.3Python

LangChain est l'une des bibliothèques Python les plus utilisées pour construire des applications à base de LLM. Ses fonctions de sérialisation ne distinguaient pas les données fournies par l'utilisateur de ses propres objets internes. Un attaquant, y compris par injection de prompt via la réponse du modèle, pouvait ainsi faire passer des données pour un objet de confiance et récupérer les secrets stockés dans les variables d'environnement. La faille est corrigée dans les versions 1.2.5 et 0.3.81 de langchain-core.

Mon analyse

Écrire ses automatisations en Python ne protège pas davantage que n8n : la sécurité dépend aussi des bibliothèques utilisées. Surtout, cet article montre que la réponse d'une IA doit être traitée comme une saisie utilisateur non fiable, jamais comme une donnée sûre.

9 décembre 2025 OWASP GenAI Security Project

OWASP Top 10 des applications agentiques 2026

OWASPAgents IARéférentiel

L'OWASP, la référence mondiale en sécurité applicative, a publié un classement des dix risques propres aux agents IA, de ASI01 (détournement de l'objectif de l'agent) à ASI10 (agents incontrôlés). On y trouve notamment le mauvais usage des outils, l'abus d'identité et de privilèges, la chaîne d'approvisionnement et l'exécution de code inattendue. La liste s'appuie sur des incidents réels de 2025, comme l'agent de Replit qui a supprimé une base de données de production.

Mon analyse

Ce référentiel me sert de grille pour auditer une automatisation. En l'appliquant à mon cas d'usage : un agent n'a que les outils strictement nécessaires (ASI02), utilise un compte de service limité (ASI03), n'installe aucune extension non vérifiée (ASI04) et n'exécute aucune action sans validation humaine.
